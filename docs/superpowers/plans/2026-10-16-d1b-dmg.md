# D1b-dmg Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Mac release tooling a disk image: `scripts/release.sh <version> --dmg` (usable with `--tester`, so the owner can try it before D2) builds `NotchMeow-<version>-mac.dmg`, with its `.sha256`, from the same app the zip holds. Tester builds keep the zip as their main file; the public release (stage 2) will ship the DMG too.

**Architecture:** One new script, `scripts/make-dmg.sh <app> <version> <outdir>`, does everything about the image with macOS's own `hdiutil`, `codesign`, `ditto` and `shasum`: it stages `NotchMeow.app` (copied with `ditto`) next to an `/Applications` symlink, makes a compressed read-only image named `NotchMeow <version>`, seals it (ad hoc today), then proves what it made by attaching it read-only in a private mount root and looking inside. `release.sh` learns a second flag, `--dmg`, and calls the script from the tester block only; the signed release refuses `--dmg` until D2, which fills one clearly named function. No third-party tool, no `.DS_Store`, no AppleScript. `scripts/test-release-tools.sh` builds real images from a tiny fake app in a temp folder.

**Tech Stack:** Bash 3.2 (macOS), `hdiutil` (create, verify, attach, detach, imageinfo), `codesign`, `ditto`, `shasum`, `PlistBuddy`. macOS only; nothing here runs on the Windows or Linux runners.

**Spec:** `docs/superpowers/specs/2026-10-08-release-prep-design.md` (sub-project D; sections 2 "The Mac tester build" and the stage 2 note "signing and notarization are D2"). The owner's decision of 2026-10-15: tester builds keep the zip; the public release adds a DMG. The existing tools are built by `docs/superpowers/plans/2026-10-08-d1-tools.md`; read its "Global Constraints" and Task 3 (the tester block) before starting.

**Base:** branch `d1b/dmg`, created from `notchmeow/rebrand` at `dc91b739` or later. No other plan touches `scripts/release.sh`, `scripts/test-release-tools.sh` or `docs/testers.html` at the moment; if one has merged since, rebase on it before Task 1.

## Global Constraints

Every task's requirements include this section.

- **Tester builds keep the zip.** `release.sh <version> --tester` with no `--dmg` must behave exactly as today: the same three files, the same `NOTES.txt`. `--dmg` only adds files.
- **The file and its names.** `NotchMeow-<version>-mac.dmg` and `NotchMeow-<version>-mac.dmg.sha256`, in the same folder as the zip (`/tmp/notchmeow-release-<version>/`, or `NM_TESTER_OUT`). The volume is named `NotchMeow <version>` (for example `NotchMeow 0.9.4`). It holds `NotchMeow.app` and a symlink `Applications` pointing at `/Applications`, and nothing else a user can see.
- **Format.** `UDZO` (zlib, read-only) by default, on an `APFS` volume, both passed explicitly so a change of `hdiutil`'s defaults cannot change the product. `NM_DMG_FORMAT=ULFO` is the one switch for lzfse (see "The format choice").
- **Apple's tools only.** `hdiutil`, `codesign`, `ditto`, `shasum`, `PlistBuddy`, `readlink`, `mktemp`. No `create-dmg`, no `appdmg`, no Homebrew, no Python for the image, no AppleScript, no Finder scripting, no `.DS_Store`.
- **Plain window.** The first version has no background picture and no fixed icon positions. A styled window is a later polish step (see "What a styled window would need"), not part of this plan.
- **Signing.** In tester mode the DMG is signed ad hoc, like the app and the zip. `release.sh <version> --dmg` without `--tester` (the signed release) is refused with a message that names D2, because this plan does not notarize, staple or touch a Developer ID. The hook for D2 is one function, `dmg_seal`, in `scripts/make-dmg.sh`.
- **Nothing outside the temp folder is touched.** The image is never mounted under `/Volumes` and never near `/Applications`: every mount uses `-mountroot` on a folder `make-dmg.sh` made with `mktemp -d`, with `-nobrowse -readonly -noverify -noautoopen`. A mount is detached on every exit path (a `trap`), failures included, and a failed run leaves no `.dmg` behind.
- **Tests never launch an app.** The fake app is a three-line shell script in a bundle; it is signed ad hoc and never run. The real tester build of Task 4 is built, inspected and mounted, never opened.
- **`release.sh` stays small and its pins stay true.** The tester block still must not contain `notarytool`, `stapler`, `git tag`, `git push`, `gh `, `ls-remote` or `find-identity` (the test greps the block for those, comments removed, so **a line of `NOTES.txt` text such as "through" or "though" would trip the `gh ` pin: avoid words that end in "gh" followed by a space in the heredoc text**). The signed release's lines do not move except for the argument parsing in Task 2.
- **Commits** are local only, never pushed, and only the files each task's commit step lists. Each message ends with `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>` (or the model that wrote it). Messages go through `git commit -F <file>`.

## The format choice

`hdiutil create -srcfolder … -format` takes any `convert` format. Two matter:

- **`UDZO`** (zlib-compressed, read-only). The `hdiutil create -srcfolder` default. Readable by every macOS since 10.2, which includes the app's floor of macOS 15 with room to spare, and by the tools a tester might use to peek inside (`7z`, `dmg2img`, Keka). Slightly slower to build and to open than lzfse, with a similar size for an app bundle.
- **`ULFO`** (lzfse-compressed, read-only). Smaller and faster to decompress on Apple silicon, but readable only on macOS 10.11 and later, and not by the third-party unpackers.

Chosen: **UDZO**, because the one thing that must not go wrong is a tester or a customer being unable to open the file, and the size gain of ULFO on a ~25 MB app is a few megabytes. `NM_DMG_FORMAT=ULFO` switches it for one build (Task 1 tests that it works), so the owner can compare the two on the real app and decide without a code change. The filesystem inside is **APFS**, named explicitly: macOS 15 reads it natively, it is `hdiutil`'s default today, and HFS+ is the legacy choice.

## What a styled window would need (not in this plan)

A styled window is the background picture and the icon placement (app on the left, arrow, `Applications` on the right) that appears when the DMG opens. It lives in a hidden `.DS_Store` file inside the image plus a hidden `.background/` folder with the picture. There is no `hdiutil` flag for it. The two ways to get it:

1. **Drive Finder:** make a read/write image (`hdiutil create -type UDIF -fs APFS -size …`), attach it with a mount point Finder shows (so no `-nobrowse`), copy the app, the symlink and `.background/bg.png` in, run an AppleScript through `osascript` that tells Finder to open the window, set `current view` to icon view, `icon size`, `background picture`, window bounds and each icon's position, wait for the `.DS_Store` to be written, detach, then `hdiutil convert … -format UDZO`. It needs a logged-in GUI session and the one-time "Terminal wants to control Finder" Automation prompt, and it is timing-dependent. This is what `create-dmg` automates, and it is why it is flaky on CI.
2. **Write the `.DS_Store` bytes ourselves** (a documented-by-reverse-engineering binary format: `Iloc`, `bwsp`, `icvp` records and a `pBBk` background alias). Deterministic and headless, but it means maintaining a parser/writer for an undocumented file.

Either is a polish step of its own (a picture in NotchMeow's style, a design the owner approves, a test that the window opens with the right layout on a real Mac). The plain image is fully usable: Finder shows the two items in its default view and the user drags one onto the other. If the owner wants the styled window, it becomes `D1c-dmg-style` with route 1 behind an `NM_DMG_STYLE=1` switch, so the plain build stays the default and the robust path.

## Dry run of the `hdiutil` commands (2026-10-16)

Run on this Mac (macOS 27.0.1) in a scratch folder with a three-line fake `NotchMeow.app` signed ad hoc; nothing outside the scratch folder was touched and the image was detached afterwards. What each flag does (from `man hdiutil`) and what was seen:

| Command | Flags, and why | Seen |
|---|---|---|
| `ditto NotchMeow.app stage/NotchMeow.app`, `ln -s /Applications stage/Applications` | `ditto` keeps resource forks, xattrs and the code signature; `cp -R` can lose them | Same app, `codesign --verify --deep --strict` still passed on the copy |
| `hdiutil create -quiet -srcfolder stage -volname "NotchMeow 7.7.7" -fs APFS -format UDZO out.dmg` | `-srcfolder` builds the image from a folder and sizes it itself (no `-size`); `-volname` is the Finder name; `-fs APFS` and `-format UDZO` pinned; `-quiet` keeps only the exit status; no `-ov`, so an existing file is an error | exit 0, 19 KB image, about 20 s the first time (APFS container set-up) |
| `hdiutil verify -quiet out.dmg` | checks the image's own checksums | exit 0 |
| `hdiutil imageinfo -format out.dmg` | prints only the format (`UDZO`) | `Format: UDZO`, plus a "deprecated, use `diskutil image info`" warning on stderr; stderr is dropped, stdout read |
| `hdiutil attach -nobrowse -readonly -noverify -noautoopen -mountroot <dir> out.dmg` | `-nobrowse` keeps it out of Finder; `-readonly` forces a read-only device; `-noverify` skips the checksum run (verify did it already); `-noautoopen` never opens a window; `-mountroot` mounts under `<dir>/<volume name>` instead of `/Volumes`, which also lets the script read the volume name back from the path | mounted at `<dir>/NotchMeow 7.7.7`, a "deprecated" warning on stderr, exit 0 |
| `ls <dir>/<volume>`, `readlink <dir>/<volume>/Applications` | what is inside | `Applications`, `NotchMeow.app`; the link reads `/Applications` |
| `codesign --verify --deep --strict <dir>/<volume>/NotchMeow.app` | the signature survived the copy into the image | passed |
| `hdiutil detach -quiet <dir>/<volume>` | detach by mount path: no `/dev/diskN` parsing, and APFS images list several `/dev` nodes | exit 0, mount directory gone |
| `codesign --force --sign - out.dmg`, `codesign --verify --verbose out.dmg` | ad hoc seal of the image | "valid on disk", "satisfies its Designated Requirement" |

Two things the dry run found, which the tasks below account for: **`hdiutil attach` and `imageinfo` print a deprecation warning on this macOS** (they still work; the script discards stderr of those two calls and checks their exit status and stdout, and `create` and `verify` printed none), and **the first `create` is slow**, so the test builds each image once and shares it between assertions.

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>

<key>CFBundlePackageType</key><string>APPL</string>
<key>CFBundleShortVersionString</key><string>$2</string>

PLIST

still_mounted() { mount | grep -cF "$DMGT/tmp" || true; }

expect "no image of this test is still attached" "$(hdiutil info | grep -cF "$DMGT/" || true)" 0

mkdir -p "$DMGT/out2"

```bash
#!/usr/bin/env bash
# Builds NotchMeow-<version>-mac.dmg (and its .sha256) from a built NotchMeow.app, with macOS's own tools only.
#
#   bash scripts/make-dmg.sh <path to NotchMeow.app> <version> <existing output folder>
#
# The image holds NotchMeow.app and a link to /Applications, on a volume named "NotchMeow <version>", and nothing else a user can see. It has no
# background picture and no icon layout: a styled window needs a .DS_Store (docs/superpowers/plans/2026-10-16-d1b-dmg.md, "What a styled window
# would need"). The format is UDZO on APFS; NM_DMG_FORMAT=ULFO makes an lzfse image instead (macOS 10.11 or later).
#
# It checks what it made: the image verifies, it is sealed, and attached read-only under a folder of its own (never /Volumes, never Finder) it holds
# exactly the app and the link, the app's signature holds and the app says <version>. A mount is detached on every way out, and a failed run leaves
# no image behind. Called by scripts/release.sh --dmg; macOS only. NM_DMG_IDENTITY is the signing identity: "-" (ad hoc, the default); a Developer ID
# is D2's work and is refused for now (dmg_seal).
set -euo pipefail

die() { echo "error: $*" >&2; exit 1; }
[ $# -eq 3 ] || { echo "usage: bash scripts/make-dmg.sh <path to NotchMeow.app> <version> <existing output folder>" >&2; exit 2; }
APP="$1"
VERSION="$2"
OUT="$3"
FORMAT="${NM_DMG_FORMAT:-UDZO}"
IDENTITY="${NM_DMG_IDENTITY:--}"

case "$FORMAT" in
  UDZO|ULFO) ;;
  *) die "NM_DMG_FORMAT is '$FORMAT': use UDZO (the default) or ULFO" ;;
esac
[[ "$VERSION" =~ ^(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$ ]] || die "'$VERSION' is not a version: use three whole numbers, like 0.9.0"
[ -d "$APP" ] && [ "$(basename "$APP")" = "NotchMeow.app" ] || die "$APP is not a NotchMeow.app"
[ -d "$OUT" ] || die "$OUT is not a folder"

DMGNAME="NotchMeow-$VERSION-mac.dmg"
DMG="$OUT/$DMGNAME"
VOLNAME="NotchMeow $VERSION"
[ ! -e "$DMG" ] && [ ! -e "$DMG.sha256" ] || die "$DMGNAME is already in $OUT: this script never overwrites a release file"

WORK="$(mktemp -d "${TMPDIR:-/tmp}/notchmeow-dmg.XXXXXX")"
MOUNT=""
cleanup() {
  local rc=$?
  if [ -n "$MOUNT" ] && [ -d "$MOUNT" ]; then
    hdiutil detach -quiet "$MOUNT" > /dev/null 2>&1 || hdiutil detach -quiet -force "$MOUNT" > /dev/null 2>&1 || true
  fi
  rm -rf "$WORK"
  if [ "$rc" -ne 0 ]; then rm -f "$DMG" "$DMG.sha256"; fi
}
trap cleanup EXIT

# The signing step, and the one place D2 changes: a Developer ID signature of the image, then Apple's notarization of it and the ticket stapled to it.
# Until then only the ad hoc seal exists, like the app's and the zip's in a tester build.
dmg_seal() {   # dmg_seal <dmg>
  if [ "$IDENTITY" = "-" ]; then
    codesign --force --sign - "$1" > /dev/null 2>&1 || die "codesign could not seal the image"
  else
    die "signing the image with a Developer ID is D2's work (NM_DMG_IDENTITY must be -)"
  fi
}

# 1. Stage: ditto keeps the code signature, the extended attributes and the resource forks that cp -R can lose.
mkdir "$WORK/stage" "$WORK/mnt"
ditto "$APP" "$WORK/stage/NotchMeow.app"
ln -s /Applications "$WORK/stage/Applications"

# 2. Make the image. -srcfolder sizes it; no -ov (an existing file was refused above); -quiet keeps only the exit status.
hdiutil create -quiet -srcfolder "$WORK/stage" -volname "$VOLNAME" -fs APFS -format "$FORMAT" "$DMG" || die "hdiutil create failed"

# 3. Seal it, then prove it. (imageinfo and attach print a deprecation notice on stderr on recent macOS; stdout and the exit status are what is read.)
dmg_seal "$DMG"
codesign --verify "$DMG" > /dev/null 2>&1 || die "the sealed image does not verify"
hdiutil verify -quiet "$DMG" || die "hdiutil verify rejected the image"
GOT_FORMAT=$(hdiutil imageinfo -format "$DMG" 2> /dev/null | sed -n 's/^Format:[[:space:]]*//p')
[ "$GOT_FORMAT" = "$FORMAT" ] || die "the image is '$GOT_FORMAT', not $FORMAT"

MOUNT="$WORK/mnt/$VOLNAME"
hdiutil attach -nobrowse -readonly -noverify -noautoopen -mountroot "$WORK/mnt" "$DMG" > /dev/null 2>&1 || die "the image would not attach"
[ -d "$MOUNT" ] || die "the volume is not named '$VOLNAME'"
[ "$(ls "$MOUNT" | tr '\n' ' ')" = "Applications NotchMeow.app " ] || die "the image should hold NotchMeow.app and Applications and nothing else, it holds: $(ls "$MOUNT" | tr '\n' ' ')"
[ -L "$MOUNT/Applications" ] && [ "$(readlink "$MOUNT/Applications")" = "/Applications" ] || die "Applications in the image is not a link to /Applications"
codesign --verify --deep --strict "$MOUNT/NotchMeow.app" > /dev/null 2>&1 || die "the app in the image is not signed, or its signature does not hold"
IN_IMAGE=$(/usr/libexec/PlistBuddy -c "Print :CFBundleShortVersionString" "$MOUNT/NotchMeow.app/Contents/Info.plist")
[ "$IN_IMAGE" = "$VERSION" ] || die "the app in the image says $IN_IMAGE, not $VERSION"
hdiutil detach -quiet "$MOUNT" > /dev/null 2>&1 || hdiutil detach -quiet -force "$MOUNT" > /dev/null 2>&1 || die "the image would not detach"
MOUNT=""

# 4. The checksum, in the shape `shasum -a 256 -c` reads when run in the output folder.
(cd "$OUT" && shasum -a 256 "$DMGNAME" > "$DMGNAME.sha256")
echo "✓ $DMGNAME ($FORMAT, volume '$VOLNAME', sealed with $([ "$IDENTITY" = "-" ] && echo "an ad hoc signature" || echo "$IDENTITY"))"
```

Then: `chmod +x scripts/make-dmg.sh` (the other scripts are run with `bash`, and `git ls-files -s scripts/release.sh` shows their mode: match it).
