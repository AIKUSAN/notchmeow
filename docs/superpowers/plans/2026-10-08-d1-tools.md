# D1-tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the first tester round (0.9.0) its Mac tools: one version number on every platform (`scripts/set-version.sh` writes it, `scripts/check-versions.sh` proves it), the tester build (`scripts/release.sh <version> --tester`: ad hoc signed, zipped, checksummed, with notes), the Mac's three permission prompts in English, the version check in the Windows and Linux workflows' manual runs, and the brief of the Mac QA session (`docs/QA-MAC.md`). Nothing is signed, notarized, tagged, pushed or published, and no app is launched by this plan.

**Architecture:** One awk program, `scripts/version-fields.awk`, knows which line of which file holds a version. `set-version.sh` writes through it and `check-versions.sh` reads through it, so the two cannot disagree about a line; both source `scripts/version-fields.sh` for the list of fields. `release.sh` gets its third mode as one block placed in front of the signed release's own steps and ending in `exit 0`, so no line of the signed release moves. Everything is tested by one script, `scripts/test-release-tools.sh`, on temporary git copies of the version files, with stub `xcodegen` and `xcodebuild` for the refusals; the real build runs once, in a throwaway clone, in Task 6.

**Tech Stack:** Bash 3.2 (macOS) and POSIX awk (the version tools also run on the Windows and Linux runners, in Git Bash and mawk), XcodeGen, `xcodebuild`, `codesign`, `lipo`, `ditto`, `shasum`, Python 3 for the edit scripts and one JSON check, GitHub Actions YAML.

**Spec:** `docs/superpowers/specs/2026-10-08-release-prep-design.md` (sub-project D, stage 1, approved by the owner on 2026-10-08). Sections 1 ("One version number everywhere"), 2 ("The Mac tester build"), 3 ("The only workflow change") and 6 ("The Mac QA session") are built here; section 7 lists what D1-tools delivers. Read the whole spec before starting.

**Base:** branch `d1/tools`, created from `notchmeow/rebrand` at `940c6fe`, after the small fixes after B have merged (`docs/superpowers/plans/2026-10-08-small-fixes-after-b.md`, branch `fixes/after-b`: that plan also edits `.github/workflows/build.yml`, `README.md` and `CHANGELOG.md`). `git merge-base --is-ancestor 940c6fe HEAD` must succeed. This plan touches neither `README.md` nor `CHANGELOG.md`, and its one `build.yml` insertion is anchored on the `Build` step, so it applies the same whether or not the small fixes' own step is there yet (Task 4 proves both). D1-site runs beside this plan in its own worktree and touches other files (`docs/index.html`, `docs/testers.html`, `docs/site.css`, `docs/assets/`, the render scripts, `README.md`); `docs/QA-MAC.md` is the only file of this plan inside `docs/`. This plan changes no pixel and no behaviour of either app: the only change under `NotchBuddy/` is the wording of three permission prompts in `project.yml` and the two Info.plists generated from it.

## Global Constraints

Every task's requirements include this section. Values are copied from the spec.

- **One version, three whole numbers (spec §1).** `0.9.0`: no `v`, no fourth part, no leading zero, because macOS reads `CFBundleShortVersionString` that way. `set-version.sh` writes it into exactly these fields and nothing else: `NotchBuddy/project.yml` (the main app's `CFBundleShortVersionString`, and its `CFBundleVersion`, the build number, raised by one on every run), `NotchBuddy/Resources/Info.plist` (regenerated by `xcodegen`, never by hand), `windows/package.json`, the two top-level `version` fields of `windows/package-lock.json`, `windows/src-tauri/tauri.conf.json`, `windows/Cargo.toml` (`[workspace.package]`) and the `notchmeow` and `notchmeow-hook` entries of `windows/Cargo.lock`. **The App Store variant (`io.github.aikusan.notchmeow.store`) keeps its own `1.0`.** `check-versions.sh` prints every field and fails when any two differ.
- **The tester build (spec §2).** `release.sh <version> --tester` is a third mode next to the signed release and `--finish`. It runs the same checks (no uncommitted change to tracked files, a `## <version>` section in `CHANGELOG.md`, the Info.plist version) and `check-versions.sh`; it works from any branch and records the branch and the commit; it runs `xcodegen`, then a Release build signed ad hoc (`CODE_SIGN_IDENTITY=-`) that keeps the hardened runtime and the entitlements; it checks the result (`scripts/check-app-binary.sh <app> release` passes, `lipo` shows Apple silicon and Intel, `codesign --verify` passes); it writes `NotchMeow-<version>-mac.zip` (made with `ditto`), its `.sha256` and a short `NOTES.txt` (version, branch, commit, date, three install lines and the testers page's address) to `/tmp/notchmeow-release-<version>/`. **It never notarizes, tags, pushes or creates a GitHub release.** The signed mode stays as it is, for stage 2.
- **The permission prompts in English, in every target where they appear (spec §2):** `NSAppleEventsUsageDescription`: "NotchMeow uses this to jump to your terminal, send mail and control Music." `NSAccessibilityUsageDescription`: "NotchMeow uses this to read the active window's title and attach it as context." `NSLocalNetworkUsageDescription`: "NotchMeow uses this to reach an AI model server you added on your network." (The App Store target has only the third.)
- **The only workflow change (spec §3):** `check-versions.sh` also runs on manual runs (`workflow_dispatch`) of `windows.yml` and `linux.yml`, as well as on tags. Everything else in those files stays as it is: `PUBLISH: 'false'`, `retention-days: 3`, the existing tag-versus-version steps.
- **The Mac QA session (spec §6).** `docs/QA-MAC.md` is a brief only: this plan never runs it and never launches NotchMeow. Its rules are the spec's: hooks checked first; any NotchMeow in `/Applications` moved to the Trash; the tester build unzipped into `/Applications` and opened; scripted events only (`scripts/fake-subagent-events.py` and sample payloads piped into the `nm-hook` relay), never installing hooks or writing to `~/.claude`; Allow, Deny or an answer clicked only on requests the session sent itself, marked in their payload; screenshots, CPU readings and a report; the tester build left installed and quit at the end.
- **Portable where it must be.** `check-versions.sh`, `version-fields.sh` and `version-fields.awk` also run on the Windows runner (Git Bash) and the Linux runner (Ubuntu's mawk): POSIX tools only, no `sed -i`, no associative arrays, no GNU-only awk, and a checkout with CRLF line endings must read the same. `set-version.sh`, `release.sh` and the test are macOS-only.
- **Never edit `NotchBuddy.xcodeproj` by hand.** The permission strings change `project.yml`, and `xcodegen` regenerates both Info.plists. `CLAUDE.md` is edited only with the owner's OK (Task 7, Step 1).
- **Names:** the names Coucou and Mochi are reserved and are not NotchMeow's identity (`mocha` is a coat); `bash scripts/check-no-leftovers.sh` stays green.
- **Commits** are local only, never pushed, and only the files each task's commit step lists. Each message ends with `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>`, or the model that wrote it if a task had to move to Sonnet 5.5 (`nm-implementer-deep`). Messages go through `git commit -F <file>`.

## Review Focus

The spec says what the tools do. It is silent on these inputs and conditions, and each would bite a person first, most likely first. Each line names the test that pins it.

1. **A version that looks right and is not.** `0.9`, `0.9.0.1`, `v0.9.0`, `01.2.3`, `0.9.0-beta`, a trailing space or newline, ten digits, nothing at all, two arguments. Expected: refused, nothing written, exit 1 (usage mistakes 2). Tests: Task 1 ("refused, nothing changed" for twelve inputs, the two usage errors).
2. **A version file that changed shape.** A missing `Cargo.lock` entry, a Windows checkout with CRLF line endings, an Info.plist with a stale build number, fields that agree on something that is not a version. Expected: `set-version.sh` refuses before it writes, `check-versions.sh` fails and names the problem, a CRLF checkout reads the same and keeps its line endings. Tests: Task 1 ("a missing Cargo.lock entry…", "a field that cannot be found…", "a checkout with CRLF…", "an Info.plist with another build number…", "fields that agree on something that is not three whole numbers…").
3. **A run that stops half way.** `xcodegen` missing or failing after the files were written. Expected: every file back as it was, and a message. Test: Task 1 "a failing xcodegen leaves every file as it was".
4. **A tester build that is not what its commit or its name says.** An uncommitted change, a branch that is not `main`, a detached HEAD, a version the files do not say, a `CHANGELOG.md` without the section, an app built for one chip only, a debug panel left in, a lost hardened runtime. Expected: refused before the build, or failed after it with a clear message, and never `gh` required. Tests: Task 3 (the five refusals, a branch and a detached HEAD, the arguments to `xcodebuild`, no `gh` on the path) and Task 6 (`lipo`, `codesign`, the entitlements and the version in the real build).
5. **A tester build that publishes.** Any path to `git tag`, `git push`, `gh release`, `notarytool` or a Developer ID. Expected: none. Tests: Task 3 "the tester block never notarizes, tags, pushes or publishes" and Task 6 (no tag, no remote touched).
6. **The QA session clicking a real request.** A payload that is not marked as its own, or that the relay silently drops. Expected: every payload valid JSON, with a `qa-` session and a `/tmp/notchmeow-qa` project. Test: Task 5 ("the QA brief writes 11 payloads…").

```bash

#!/usr/bin/env bash
# Tests the release tools on temporary copies of the version files. Nothing in the repository is touched, nothing is built, and no app is run.
#   - set-version.sh: exactly which files and lines change, the App Store target's own 1.0 left alone, the build number up by one on every run;

#   - the three permission strings in English, in project.yml and in both Info.plists xcodegen makes from it;

#     (the build itself is checked by Task 6 of docs/superpowers/plans/2026-10-08-d1-tools.md);
#   - the QA brief's sample payloads (docs/QA-MAC.md): valid JSON, and marked as the QA session's own.
# Needs xcodegen (the macOS job installs it). Usage: bash scripts/test-release-tools.sh
set -euo pipefail
cd "$(dirname "$0")/.."
REPO="$PWD"
command -v xcodegen >/dev/null || { echo "✗ xcodegen is needed to test the version tools (brew install xcodegen)" >&2; exit 1; }
TMP="$(mktemp -d "${TMPDIR:-/tmp}/notchmeow-versions.XXXXXX")"
trap 'rm -rf "$TMP"' EXIT

pass=0
fail=0
ok() { pass=$((pass + 1)); echo "✓ $1"; }
no() {
    fail=$((fail + 1))
    echo "✗ $1"
    shift
    for line in "$@"; do printf '%s\n' "$line" | sed 's/^/    /'; done
}
expect() {   # expect <description> <got> <wanted>
    if [ "$2" = "$3" ]; then ok "$1"; else no "$1" "wanted: $3" "got:    $2"; fi
}
contains() {   # contains <description> <text> <word>
    if grep -qF -- "$3" <<<"$2"; then ok "$1"; else no "$1" "wanted a line with: $3" "got:" "$2"; fi
}

VERSION_FILES="NotchBuddy/project.yml NotchBuddy/Resources/Info.plist NotchBuddy/Resources/InfoAppStore.plist windows/package.json windows/package-lock.json windows/src-tauri/tauri.conf.json windows/Cargo.toml windows/Cargo.lock"

GIT="git -c user.name=test -c user.email=test@example.invalid -c commit.gpgsign=false"

tree() {   # tree <name>: a git repository holding copies of the version files, the tools and the changelog, and the empty folders xcodegen wants
    local d="$TMP/$1" f
    mkdir -p "$d/NotchBuddy/Sources" "$d/NotchBuddy/Assets.xcassets" "$d/NotchBuddy/Resources/sounds"
    for f in $VERSION_FILES $TOOLS CHANGELOG.md; do
        mkdir -p "$d/$(dirname "$f")"
        cp -p "$REPO/$f" "$d/$f"
    done
    (cd "$d" && git -c init.defaultBranch=main init -q && git add -A && $GIT commit -qm base)
    echo "$d"
}
field() {   # field <tree> <field>: the value the tools read
```

```bash
cat > "scripts/version-fields.awk" <<'FILEEOF'
# The one place that knows which line of which file holds a version. set-version.sh writes through it and check-versions.sh reads through it,
# so the two cannot disagree about a line. POSIX awk only: it runs in macOS's awk, mawk (Ubuntu) and gawk (Git for Windows).
#
#   awk -v f=<field> -f scripts/version-fields.awk <file>              prints the field's value, once per matching line (a healthy file: one line)
#   awk -v f=<field> -v new=<value> -f scripts/version-fields.awk <file>   prints the file with that value in place of the old one
#
# The fields: yml, yml_build, yml_store (project.yml: the main app's version, its build number, and the App Store target's version); plist,
# plist_build (Info.plist); pkg (package.json); lock_top, lock_root (the two top-level versions of package-lock.json); tauri (tauri.conf.json);
# cargo ([workspace.package] in Cargo.toml); lock_app, lock_hook (the notchmeow and notchmeow-hook entries of Cargo.lock).

# The value on a line: the last "quoted" text, or the text of a <string> tag.
function val(s,   a, n) {
    if (s ~ /<string>/) { sub(/.*<string>/, "", s); sub(/<\/string>.*/, "", s); return s }
    n = split(s, a, "\"")
    return a[n - 1]
}

# The same line with another value in that place.
function put(s, v,   a, n, i, r) {
    if (s ~ /<string>/) { sub(/<string>[^<]*<\/string>/, "<string>" v "</string>", s); return s }
    n = split(s, a, "\"")
    a[n - 1] = v
    r = a[1]
    for (i = 2; i <= n; i++) r = r "\"" a[i]
    return r
}

{
    cr = ""
    if (sub(/\r$/, "")) cr = "\r"     # a checkout with Windows line endings reads the same, and is written back the same
    hit = 0
    if (f == "yml" || f == "yml_build" || f == "yml_store") {
        if ($0 ~ /^[^ #]/) top = $1
        if (top == "targets:" && $0 ~ /^  [A-Za-z]+:$/) tgt = $1
        want = (f == "yml_store") ? "NotchMeowAppStore:" : "NotchBuddy:"
        key = (f == "yml_build") ? "CFBundleVersion" : "CFBundleShortVersionString"
        hit = (top == "targets:" && tgt == want && index($0, "        " key ": \"") == 1)
    } else if (f == "plist" || f == "plist_build") {
        key = (f == "plist_build") ? "CFBundleVersion" : "CFBundleShortVersionString"
        hit = (prev == "<key>" key "</key>" && $0 ~ /<string>/)
        prev = $0
        sub(/^[ \t]+/, "", prev)
        sub(/[ \t]+$/, "", prev)
    } else if (f == "pkg" || f == "tauri" || f == "lock_top") {
        hit = ($0 ~ /^  "version": "/)
    } else if (f == "lock_root") {
        if ($0 ~ /^    "": [{]$/) inroot = 1
        else if ($0 ~ /^    [}],?$/) inroot = 0
        hit = (inroot && $0 ~ /^      "version": "/)
    } else if (f == "cargo") {
        if ($0 ~ /^\[/) sect = $0
        hit = (sect == "[workspace.package]" && $0 ~ /^version = "/)
    } else if (f == "lock_app" || f == "lock_hook") {
        want = (f == "lock_app") ? "notchmeow" : "notchmeow-hook"
        if ($0 ~ /^\[\[package\]\]/) nm = ""
        else if ($0 ~ /^name = "/) nm = val($0)
        hit = (nm == want && $0 ~ /^version = "/)
    } else {
        print "version-fields.awk: no field called '" f "'" > "/dev/stderr"
        exit 2
    }
    if (hit && new == "") print val($0)
    else if (hit) print put($0, new) cr
    else if (new != "") print $0 cr
}
FILEEOF
```

```bash
cat > "scripts/version-fields.sh" <<'FILEEOF'
# Sourced by set-version.sh and check-versions.sh (not run on its own): where every version of NotchMeow lives.
# The lines themselves are found by version-fields.awk, which both scripts go through.
# Bash 3.2 (macOS) and Git for Windows' bash are enough: no arrays, no associative arrays.

VF_ROOT="${VF_ROOT:-$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)}"
VF_AWK="$VF_ROOT/scripts/version-fields.awk"

# The fields that must all carry one version, in the order check-versions.sh prints them.
VF_FIELDS="yml plist pkg lock_top lock_root tauri cargo lock_app lock_hook"

# The file a field lives in, relative to the repository root.
vf_file() {
    case "$1" in
        yml|yml_build|yml_store) echo NotchBuddy/project.yml ;;
        plist|plist_build) echo NotchBuddy/Resources/Info.plist ;;
        pkg) echo windows/package.json ;;
        lock_top|lock_root) echo windows/package-lock.json ;;
        tauri) echo windows/src-tauri/tauri.conf.json ;;
        cargo) echo windows/Cargo.toml ;;
        lock_app|lock_hook) echo windows/Cargo.lock ;;
        *) return 1 ;;
    esac
}

# What the field is called in the file.
vf_label() {
    case "$1" in
        yml) echo "CFBundleShortVersionString (NotchBuddy target)" ;;
        yml_build) echo "CFBundleVersion (NotchBuddy target)" ;;
        yml_store) echo "CFBundleShortVersionString (NotchMeowAppStore target)" ;;
        plist) echo "CFBundleShortVersionString" ;;
        plist_build) echo "CFBundleVersion" ;;
        pkg|tauri) echo "version" ;;
        lock_top) echo "version (top of the file)" ;;
        lock_root) echo 'version (packages[""])' ;;
        cargo) echo "version ([workspace.package])" ;;
        lock_app) echo 'version (package "notchmeow")' ;;
        lock_hook) echo 'version (package "notchmeow-hook")' ;;
        *) return 1 ;;
    esac
}

# vf_get <field>: prints the field's value. Fails, printing nothing, unless the field's line is there exactly once.
vf_get() {
    local out n
    out=$(awk -v f="$1" -f "$VF_AWK" "$VF_ROOT/$(vf_file "$1")") || return 1
    n=$(printf '%s\n' "$out" | grep -c .)
    [ "$n" = 1 ] || return 1
    printf '%s\n' "$out"
}

# vf_put <field> <value>: changes that one line of the file in place. The file's mode and every other line stay as they are.
vf_put() {
    local file tmp
    file="$VF_ROOT/$(vf_file "$1")"
    tmp=$(mktemp "${TMPDIR:-/tmp}/nm-version.XXXXXX") || return 1
    if awk -v f="$1" -v new="$2" -f "$VF_AWK" "$file" > "$tmp"; then
        cat "$tmp" > "$file"
        rm -f "$tmp"
    else
        rm -f "$tmp"
        return 1
    fi
}

# vf_whole <text>: succeeds for three whole numbers with dots between them (0.9.0), without leading zeros: what macOS and Cargo both accept.
vf_whole() {
    local re='^(0|[1-9][0-9]{0,8})(\.(0|[1-9][0-9]{0,8})){2}$'
    [[ "$1" =~ $re ]]
}
FILEEOF
```

The brief's commands are the one thing no test runs, so try them once against a stand-in for the app: a small Python server that listens on the socket the relay uses, under a `HOME` of its own (a short one: a socket path is limited to 104 bytes, so the folder is under `/tmp` if `${TMPDIR}` is too long for it), answers a permission request with "allow" and a question with an answer, and logs what it receives. **This never touches the real app, its socket or `~/Library/Application Support/NotchMeow`.** It runs the brief's own payload block, the relay as the app writes it (taken from `HookServer.swift`), and the demo script. ```bash

```bash
# A stand-in for the app's socket, for checking the QA brief's commands. Listens on $HOME/Library/Application Support/NotchMeow/nm.sock.
# Logs each payload; answers PermissionRequest with allow after 1 s, ask_user_question with an answer, everything else with ok.
import json, os, socket, sys, threading, time
home = os.environ["HOME"]
d = os.path.join(home, "Library", "Application Support", "NotchMeow")
os.makedirs(d, exist_ok=True)
path = os.path.join(d, "nm.sock")
if os.path.exists(path): os.unlink(path)
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM); s.bind(path); s.listen(16)
log = open(os.path.join(home, "standin.log"), "a")
def handle(c):
    raw = b""
    while not raw.endswith(b"\n"):
        ch = c.recv(4096)
        if not ch: break
        raw += ch
    try: p = json.loads(raw)
    except Exception as e:
        log.write("BAD JSON %r\n" % raw[:80]); log.flush(); c.close(); return
    ev = p.get("hook_event_name", ""); kind = p.get("nm_kind", "")
    log.write("%s %s %s %s\n" % (ev or kind, p.get("session_id"), p.get("cwd"), p.get("tool_name"))); log.flush()
    if ev == "PermissionRequest":
        time.sleep(1); c.sendall(b'{"permissionDecision":"allow"}\n')
    elif kind == "ask_user_question":
        time.sleep(1); c.sendall(b'{"permissionDecision":"answer","answers":{"NM-QA: which cat is the cutest?":"Shrimpy"}}\n')
    else:
        c.sendall(b'{"ok":true}\n')
    c.close()
while True:
    c, _ = s.accept(); threading.Thread(target=handle, args=(c,), daemon=True).start()
FILEEOF
```
